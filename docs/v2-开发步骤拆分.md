> **工作方式**：按 S→A→B→C→D 顺序推进，**每个步骤开工前单独商议一次**（确认做法与取舍后再动代码）。

## S 组 · 地基（先做，一次性）

### S1 数据表落地
- **交付**：`db.py` 纯追加 4 个模型类；`models.py` 纯追加 Pydantic 模型。
  - `chief_goals`（kind=weight|rule|preference, key, value, updated_at, source_quote, note）
  - `chief_sessions`（owner_id, status, created_at）
  - `chief_turns`（session_id, role=draft|review|final, prompt_text, reply_text, snapshot_json, created_at）
  - `chief_actions`（session_id, kind=rebalance|rule, target, target_weight|new_value, reason, trigger, source_quote, status, executed_at）
- **涉及文件**：`db.py`（追加）、`models.py`（追加）
- **验收**：本地起服务无报错；`sqlite` 里 4 张新表存在；现有表结构未变。
- **商议点**：
  1. 表名前缀统一 `chief_` 还是沿用无前缀？（建议 `chief_`，一眼可辨属 v2）
  2. `chief_turns` 三轮行合并方案是否采纳（原设计是 `briefings` 三行）——**建议合并**，少一表、语义不变。
  3. 是否需要 `owner_id` 全套（当前实际单人使用，但保留多用户隔离成本极低）——建议保留。

### S2 页面骨架接入
- **交付**：`06-pages.js` 改 3 处 1 行（`ROUTES` / `viewNeedsAuth` / `switch`）；`index.html` 纯追加导航两条 + 脚本一行；新建 `static/js/09-chief.js`（先渲染占位页）。
- **涉及文件**：`static/js/06-pages.js`（3 行）、`static/index.html`（追加）、`static/js/09-chief.js`（新）
- **验收**：`#/chief` 可直链、刷新停在原页、游客访问自动弹登录门禁、导航高亮与移动端抽屉入口正常。
- **商议点**：
  1. 导航文案：叫「**主事**」还是「**主事工作台**」？（顶栏空间紧，建议「主事」）
  2. 入口位置：放在「交易」之后、「设置」之前？
  3. 游客策略：直接隐藏入口（像自动分类按钮那样）还是显示但点击弹登录？（建议后者，与圆桌一致）

## A 组 · 目标与规则审视卡（期 1，可独立先上）

> 该组是 B 组提示词的上下文头来源，**优先做**。全部内嵌在主事工作台页，不新建设置页。

### A1 目标权重配置（按行业）
- **交付**：行业内目标占比的增删改；行业候选来自 `projects.category` 现有值（半导体 / 宽基指数 / 海外债券 / 电力设备…）；留空 = 不限。
- **端点**：`GET/PUT /api/chief/goals`
- **涉及文件**：`chief.py`（新）、`app.py`（追加端点）、`static/js/09-chief.js`
- **验收**：设半导体 20% → 刷新后仍在；列表页与提示词上下文头能读到。
- **商议点**：
  1. **按行业 vs 按标的**：先只做按行业？还是同时支持按标的（更精细但配置重）？——建议先按行业。
  2. 目标值形态：百分比（%）还是金额？——建议百分比。
  3. 未配置的行业如何显示（"—" / 0% / 归入"其他"）？

### A2 纪律规则配置
- **交付**：规则项配置，如「单一标的 ≤15%」「单一行业 ≤40%」；可增删改。
- **商议点**：
  1. 规则形态：**结构化条目**（类型=单一标的/单一行业，比较符，阈值）还是**自由文本**？
     ——建议结构化（平台要能自动算偏离与标红），自由文本留给 A3。
  2. 默认规则给几条？（建议：单一标的 ≤15%、单一行业 ≤40%，可改）
  3. 违规在界面上如何呈现（红标 / 黄标 / 仅提示）？

### A3 风险偏好 / 约束
- **交付**：自由文本 + 少量开关（如"是否允许换仓"、最大回撤容忍）。
- **商议点**：这一项是否必要？会不会与 A2 重复？（**建议最小化**：只留一个自由文本框 + 一个"允许换仓"开关，其余等真需要再加）

### A4 现状对照视图（当前 vs 目标 + 偏离）
- **交付**：按行业/标的聚合当前占比 → 与目标对比 → 偏离值 + 超配/低配标记；违反 A2 规则的项标红。
- **依赖**：A1
- **商议点**：
  1. 偏离阈值怎么定（绝对差 >3% 才提示？还是一律显示）？
  2. 聚合口径：按市值？还是按成本？——建议**市值**。
  3. 是否需要 Top3 集中度一行？

### A5 近期政策与市场变化区块
- **交付**：复用资讯卡片（`news_items.ai_*`）渲染近期条目，★ 标与持仓相关；供规则审视对照。
- **涉及文件**：`chief.py`（复用 `select_news_for_prompt` 的选条逻辑）
- **商议点**：
  1. 取多少条、什么时间窗（近 3 天 / 7 天）？
  2. 是否只显示"市场/政策类"（按 `ai_tags` 过滤）还是全部？

## B 组 · 三轮提示词（期 2）

### B1 提示词装配后端（上下文头）
- **交付**：`chief.py` 组装「上下文头」：持仓快照（复用 `app._snapshot_prompt_text`）+ 目标配置（A1/A2/A3 渲染）+ 最近一次会话与执行结果。
- **商议点**：
  1. 上下文头的**段落顺序**与标题命名（影响主事理解）。
  2. 是否带"上次调仓执行结果"？——建议带（呼应"最近调仓与执行结果"设计）。

### B2 素材体接入
- **交付**：资讯卡片（`news_prompt_block` 复用）+ 圆桌席位结论**按标的聚合**（共识方向 + 分歧点）。
- **商议点**：
  1. **席位结论聚合算法**：同向计数≥2/3 判为共识、否则列分歧？还是只列各席位首句？
  2. 圆桌未跑过时怎么办（只带资讯 / 提示先跑圆桌）？——建议只带资讯，不阻塞。

### B3 初稿轮（→ Gemini）
- **交付**：生成提示词 → 文本框展示 → 一键复制 → 粘贴原文 → 保存（写 `chief_turns.role=draft`）。
- **商议点**：
  1. 提示词**全文指令尾措辞**（这是最关键的一处，建议先出草稿单独过一遍）。
  2. 原文保存后是否可再编辑（改错别字）？——建议可编辑。

### B4 审查轮（→ ChatGPT）
- **交付**：自动内嵌 B3 初稿原文 → 生成 → 复制 → 保存。
- **商议点**：反向指令的措辞（"只做审查、不另起方案"的力度）。

### B5 终稿轮（→ Gemini）
- **交付**：自动内嵌 B4 审查 → 生成 → 复制 → 保存（**执行依据**）。
- **商议点**：是否要求终稿显式回答"采纳/未采纳哪些审查意见及原因"？——建议要（可追溯）。

## C 组 · 标注与跟踪（期 3）

### C1 动作行候选提取
- **交付**：前端按编号 / 段落 / 行首关键词（`减仓|加仓|买入|卖出|规则|建议`）拆终稿 → 候选清单 → 用户勾选 / 删改 / 确认。
- **商议点**：
  1. 关键词表怎么定、是否可配置？
  2. 候选误提/漏提时，手动新增行是否必须（**建议必须支持**）。

### C2 调仓组标注
- **交付**：每条标 计划 / 部分 / 已完成 / 取消，可改目标权重与备注。
- **商议点**："部分"如何表达（百分比 / 数量）？

### C3 规则组标注
- **交付**：每条标 采纳 / 未采纳；采纳即写回 `chief_goals` 并在 `note` 留痕（哪期 / 什么背景 / 依据哪次终稿）。
- **商议点**：留痕展示在哪（规则条目下「变更记录」小字 / 独立区域）？

### C4 成交回填打通 Feedback
- **交付**：调仓行标记完成 → 引导回填实际成交 → 进现有「建议→反馈→再预测」闭环。
- **商议点**：是否自动带出标的与建议方向，还是完全手填？

## D 组 · 历史与语义（期 4，可提前）

### D1 历史会话
- **交付**：底部折叠区，日期倒序（日期 / 状态 / 调仓数 / 规则变更数）→ 点开回溯三回合原文 + 动作行 + 执行结果。
- **商议点**：默认折叠还是展开最近一期？

### D2 圆桌语义调整
- **交付**：席位输出改为"分析结论"措辞；命中率统计改名为「素材质量 / 分析师参考度」。
- **商议点**：改名是否会影响已有截图/文档引用？（建议只改前端文案，不动数据）

### D3 规则留痕查询
- **交付**：可查某次规则变更发生在哪期、什么背景、依据哪次主事建议（读 `chief_goals.note`）。
