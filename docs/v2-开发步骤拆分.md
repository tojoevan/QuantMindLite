### A1 目标权重配置（**按标的**）✅ 已完成（commit `75c2b88`）

- **用户决策**：目标权重**按标的**，不按行业 —— 「标的可以让 AI 了解实际投入领域，调仓才准确」。
  （推翻了原方案"按行业"，文档 §6.1 已同步。）
- **交付**：
  - 单表 5 列：**标的**（名 + 代码）｜**领域**（分类 tag）｜当前占比｜目标权重% 输入框｜**偏离**（当前 − 目标）
  - 输入即实时重算该行偏离与底部目标合计；合计 >100% 标红（不阻止保存）
  - 保存为**全量覆盖**：`weight <= 0` 视为未配置，显示「—」且不落库
- **数据**：`chief_goals` 表 `kind='weight'`，`key="p:<project_id>"`，`value` 为百分比字符串。
  行业占比由标的按分类汇总得出，**不单独存**。
- **端点**：`GET /api/chief/goals?kind=weight`、`PUT /api/chief/goals/weight`。
  直接追加在 `app.py` 的 `app.mount` 之前 —— A 组尚不需要独立 `chief.py`（B 组提示词装配时再建）。
- **涉及文件**：`app.py`、`db.py`（docstring 改语义）、`models.py`、`static/js/09-chief.js`、`static/style.css`、`static/index.html`
- **验收（Playwright，真实路径）**：临时用户 + 3 标的（市值 3600/2000/1200）走完
  「注册 → 建标的 → 录行情 → 点入口 → 填值 → 保存 → 刷新」：
  - 渲染 3 行按市值降序，占比 52.9% / 29.4% / 17.6%，领域 tag 正确 ✅
  - 填 30/30/40 → 偏离 +22.9%(红) / -0.6%(绿) / -22.4%(绿)，合计 100.0% ✅
  - 保存后刷新 → 值仍为 30/30/40（持久化）✅
  - 清空保存 → 后端 `items: []`（全量覆盖生效）✅
  - console / pageerror **none** ✅
- **遗留**：目标合计不强制 100%（留空=未配置，允许留现金），故不设校验拦截。

### A2 纪律规则配置 ✅ 已完成

- **三个商议点的结论**（用户：按建议处理）：
  1. 形态 = **结构化条目**；自由文本类约束留给 A3，不塞进规则表。
  2. 默认 2 条：任一单一标的 ≤15%、任一单一行业 ≤40%（可改）。
  3. 违规呈现三级：**红=违反 / 黄=接近 / 绿=达标**，不只提示。
- **数据**：复用 `chief_goals` 表 `kind='rule'`，不新建表。
  `key` = 作用范围 scope（`any_pos` / `any_cat` / `pos:<project_id>` / `cat:<行业名>`）、
  `op` = `le`（不超过）/ `ge`（不低于）、`value` = 阈值百分比。
  留痕字段（`note` / `source_quote`）留到 C3 规则组标注，本次不用。
- **端点**：
  - `PUT  /api/chief/goals/rule` —— 全量覆盖保存（阈值 ≤0 丢弃不落库）
  - `GET  /api/chief/rules/check` —— 校验**已落库**的规则（留给提示词装配用）
  - `POST /api/chief/rules/check` —— 校验**任意一组规则**（草稿也算），不落库
- **关键设计：存与算分离**。
  最初只做了 GET（按库里的规则算），结果「默认 2 条」「刚改阈值还没保存」永远显示灰色"待保存"，
  看不到红黄绿 —— 纪律规则最核心的即时反馈就丢了。改为 POST 草稿校验后：
  进页面就有红黄绿，阈值改完 400ms 自动重算，**不必先保存才知道有没有违规**。
  判定口径：le 取**最极端**的那个标的/行业（只要有一个超了就是违反），ge 取最小的；
  行业聚合只认有分类的标的，未分类标的不归属任何行业（只参与单一标的规定）。
- **界面**：目标权重卡片下方新增「纪律规则」卡片（同属一个 panel，用 h4 分区）。
  表格列：规则｜条件（≤/≥ 可切）｜阈值% 输入框｜当前（值 + 命中对象）｜状态徽章｜移除。
  底部：类型下拉（四种）+ 目标下拉（后两种才显示）+ 添加 / 保存 / 恢复默认 2 条。
  违反项同步到目标权重表：整行左侧红条 + 占比红字 + 行业标签描红。
- **涉及文件**：`app.py`、`db.py`（docstring 改语义）、`models.py`、`static/js/09-chief.js`、
  `static/style.css`、`static/index.html`、`deploy.sh`（同步排除 `.workbuddy`）
- **验收（Playwright，真实路径）**：临时用户 + 3 标的（军工 55% / 科技 45%）走完
  「进页面 → 改阈值 → 保存 → 刷新 → 添加 → 移除」，**19/19 通过**：
  - 未保存的默认 2 条即时算出 55% > 15%、55% > 40% → 双「违反」，当前值 55.0% 且命中 A军工 / 军工 ✅
  - 目标权重表：A 军工 整行红条 + 占比 55.0% 标红 + 行业标签描红 ✅
  - 改阈值 100/60（**未保存**）→ 即时变「达标/接近」，红条消失 ✅
  - 保存 → 刷新 → 仍是 2 条且阈值 100/60、状态不变（持久化）✅
  - 添加「指定标的 A 军工 ≤15%」→ 保存 → 变「违反」且 A 行重新标红 ✅
  - 移除 → 回到 2 条 ✅；console / pageerror **none** ✅
  - 清理：E2E 账号与标的已删（线上 users 5 → 1，chief_goals 0 行，integrity ok）
