# QuantMindLite v2 设计方案：主事工作台（半人工决策闭环）

> 状态：v2 设计草案 **v0.4**（设计成熟，未进入开发；§13 为 v1 上的最小影响落地方案）
> 前置版本：`v1.0.0`（已 tag 固化，含标的清单分类/筛选/排序/自动分类）
> 设计原则：平台**不做决策、不自动下单**；决策权归属主事（Gemini 决策 + ChatGPT 审查）；人工桥接（复制提示词 → 问主事 → 贴回答复）。
> v0.3 更新：并入本轮讨论结论（D2/D3/D4 已决、Q1/Q2 随 D3 消解、结构化卡片现状盘点、v2 增量收敛）。

---

## 0. 版本背景与定位

### v1 回顾（慢量化操作台）
- 核心理念：**建议 → 反馈 → 再预测** 的人机协作闭环，逐标的（micro）信号级。
- 能力：逐标的 BUY/SELL/HOLD 预测（`predictor.py`）、圆桌多 AI 席位分析、资讯工作台、论坛、组合可视化（持仓/盈亏/分类标签）。
- 短板：只回答"**这一只该买还是卖**"，缺"**我的整体组合健康吗、该往哪调**"的组合级合成。

### v2 目标
把平台从"逐标的信号"升级为"**组合级合理化建议与调控**"，引入：
1. **主事裁决**：把所有数据/分析/持仓/调整情况汇总交给顶级 AI 主事，由其给出调仓方案，用户执行。
2. **三段式串行闭环**：Gemini 初稿 → ChatGPT 反向思考 → Gemini 终稿。
3. **工作流化**：平台负责"归集 → 出提示词 → 回收跟踪"，中间由用户手工桥接，即"半人工 / 半量化"。

## 1. 核心架构转向

| 维度 | v1（否定） | v2（采用） |
|---|---|---|
| 决策来源 | 多 AI 席位各投 BUY/SELL/HOLD → 机械汇总 | 主事裁决（Gemini 决策 + ChatGPT 审查 → Gemini 终稿） |
| 圆桌定位 | 表决器（被否定） | **多模型分析层**（保留，产出分析结论，作为主事素材） |
| 平台角色 | 既是分析方又是"汇总裁判" | 信息中枢 + 执行跟踪器 |
| 闭环层级 | 逐标的信号级 | 组合级（持仓聚合 → 主事方案 → 执行跟踪） |
| 下单 | 全人工 | 全人工（不变） |

### 1.1 主事三段式闭环（D3 已决）

| 轮次 | 输入 | 模型 | 产出 |
|---|---|---|---|
| ① 初稿 | 主事提示词（上下文头 + 素材体 + 指令尾） | **Gemini** | 主调仓方案（初稿） |
| ② 反向 | Gemini 初稿 + "请反向思考审查"指令 | **ChatGPT** | 审查意见（挑刺 / 风险警示 / 修正建议） |
| ③ 终稿 | ChatGPT 审查意见 + "请综合出终稿"指令 | **Gemini** | **终稿**（吸收审查后的最终方案） |

- **ChatGPT 不产出最终方案**，只作为 Gemini 终稿的"砂纸"。
- **用户只需消化一份终稿**，可部分否决；平台只留存、不自动执行。
- 目标：**每一笔调整都经过两方分析审查、可追溯**。

## 2. 半人工工作流（阶段 0–5）

| 阶段 | 执行方 | 平台职责 |
|---|---|---|
| 0 数据归集 | 自动 | 持仓/盈亏/分类/资讯/历史反馈（v1 已具备） |
| 1 圆桌多模型分析 | 混合（见 §7.2） | 生成分析提示词 → 各席位出**分析结论** → 回填 → 汇总 |
| 2a 主事提示词（初稿版） | 平台 → 用户 | 拼装自包含提示词 → 复制给 **Gemini** |
| 3a 初稿 | **用户**（手工） | 贴 Gemini，拿回初稿 |
| 2b 审查提示词 | 平台 → 用户 | 内嵌 **Gemini 初稿** + 反向思考指令 → 复制给 **ChatGPT** |
| 3b 审查 | **用户**（手工） | 贴 ChatGPT，拿回审查意见 |
| 2c 终稿提示词 | 平台 → 用户 | 内嵌 **ChatGPT 审查意见** + 终稿指令 → 复制给 **Gemini** |
| 3c 终稿 | **用户**（手工） | 贴 Gemini，拿回终稿 |
| 4 回填 | 用户 → 平台 | 粘贴终稿原文 → 平台留存（`raw_reply`） |
| 4.5 标注 | **用户** | 从终稿中标注要执行的动作行（计划/已执行） |
| 5 实施跟踪 | 用户 + 平台 | 用户下单；平台标记状态，回写实际成交 |

> 阶段 2（出）与阶段 4（进）是平台需新建的两个接口，3/5 为用户人工桥——这是"半量化"的实体形态。

## 3. 信息架构：新增「主事工作台」页

- **入口**：顶部导航新增「主事工作台」，登录可见、游客隐藏。
- **三段式布局**：
  - **左 · 提示词生成**：按轮次（初稿 / 审查 / 终稿）一键生成对应提示词 → 复制。轮次间自动内嵌上一轮原文。
  - **中 · 调仓方案**：粘贴终稿 → 原文留存 → 人工标注动作行 → 跟踪。
  - **右/下 · 历史**：历次会话（三回合原文）与方案，可回溯、可复用。
- **主事角色**：默认 Gemini=决策（初稿+终稿）、ChatGPT=审查（反向），关系固定串行。

## 4. 阶段 2 提示词生成（出站）

### 4.0 提示词 = 三层信息包

| 层 | 内容 | 来源 | 各轮是否相同 |
|---|---|---|---|
| **上下文头** | 持仓全景（持仓/盈亏/分类/行业占比）、最近调仓与执行结果、**投资目标**（目标权重/纪律规则/风险偏好） | 平台自动算 | ✅ 一致 |
| **素材体** | 资讯要点（已评审卡片）+ 圆桌席位分析结论汇总 | v1 已有 + 轮次原文 | ✅ 一致（保证可比） |
| **指令尾** | 角色设定 + 输出要求 | 平台模板（按轮次三套） | ❌ 各轮不同 |

### 4.1 三轮指令尾（**两条主线并行**：调仓 + 规则变更）

> 用户明确：三轮提示词**均需包含**「市场与政策对规则的影响」模块——输入当前纪律规则 + 近期政策/市场变化，
> 要求主事**给出规则变更建议**，与调仓建议**并列输出、同样由用户裁定**。

| 轮次 | 调仓主线 | 规则主线 |
|---|---|---|
| **① 初稿（Gemini）** | 是否需要调仓 + 调整指南（减/加/换 + 目标权重 + 理由 + 触发条件） | 评估近期市场/政策变化是否要求调整纪律规则 → 给出**规则变更建议**（改哪条 / 改成什么 / 理由） |
| **② 反向（ChatGPT）** | 对调仓方案逐条指出问题、风险与修正建议 | **同时审查规则变更建议**（是否过度反应 / 是否遗漏政策影响） |
| **③ 终稿（Gemini）** | 修订后的最终调仓方案 | **最终规则变更建议**；均需说明采纳/未采纳哪些审查意见及原因 |

> 两条主线输出地位相同：都由主事给建议，**都由用户终裁**（调仓→执行；规则→决定是否改，改则留痕）。

### 4.2 目标配置层（**新建**，v1 缺口）
v1 没有"目标"这一层，导致席位/主事缺少评判基准。v2 需新建：
- **目标权重**：**按标的**设目标占比（可留空=未配置）
  - ✅ **已落地**（A1，commit `75c2b88`）。用户定：**按标的，不按行业** —— 标的本身带领域信息，
    主事看清"每笔钱投的是什么领域"，调仓建议才准确；行业占比由标的按分类汇总得出。
  - 存储：`chief_goals` 表 `kind='weight'`，`key="p:<project_id>"`，`value`=百分比。
- **纪律规则**：如单一标的 ≤15%、单一行业 ≤40%（A2，待落地）
- **风险偏好 / 约束**：如最大回撤容忍、是否允许换仓（A3，待落地）

> 该层即此前演进路径中的 **B 层**，是"合理化建议"的依据来源。

#### 4.2.1 纪律规则需「每期审视」（用户明确）
- 规则本身**不频繁变动**，但**政策与市场会对其产生影响** → 不能"设一次就固定"。
- 因此每期决策前必须有**规则复核环节**：展示当前规则 + 近期政策/市场变化，判断是否需要调整。
- **审视方式（用户已决）**：不靠用户拍脑袋，而是**由主事给建议**——
  三轮提示词（初稿 / 反向 / 终稿）**均含**「市场与政策对规则的影响」模块，
  主事据此给出**规则变更建议**，与调仓建议**并列**、同样由用户裁定（详见 §4.1）。
- 平台侧保留「每期审视」入口：展示当前规则 + 近期政策/市场变化（复用资讯卡片），供用户对照主事建议做裁定。
- 设计含义：目标配置层不是纯静态配置，需带**调整留痕**（何时 / 什么背景 / 改了什么 / 依据哪次主事建议）。

### 4.3 截断策略（D5 已决：**自适应**）
| 对象 | 策略 |
|---|---|
| 资讯条数 | 沿用 v1 `PROMPT_TOPK=10` + 市场级保底 3 条，**不动** |
| 持仓明细 | ≤20 个全带明细；>20 时按市值 **Top15** 带明细，其余**按行业聚合成摘要行**（行业 / 合计占比 / 合计盈亏） |
| 席位结论 | 不逐席位贴全文，改为**按标的聚合**：每标的给"共识方向 + 分歧点"（仅分歧处展开席位原话） |

- 阈值设为**可调参数**（设置项 / 常量），不写死。
- 主事**角色**（决策 / 审查）决定指令措辞风格；**不区分具体型号版本**（Q3 已决：型号由用户在各自平台自行选用）。
- ⚠️ 席位结论改"标的视角"会弱化单个席位存在感，属有意取舍（对主事更易用）。

## 5. 阶段 4 主事答复回填（入站）

采用 **自然语言回填 + 原文留存 + 人工标注**（D2 已决，**不强制固定表格、不依赖二次 LLM 解析**）：

- 提示词要求主事输出**两条主线**：①「是否需要调仓」+「调整指南」；②「规则变更建议」（市场/政策影响）。均为自然语言。
- 用户将终稿原文粘贴回平台 → 保存 `raw_reply`（原文备查）。
- 用户从原文中**人工标注**出要采纳的动作行（**调仓 / 规则变更按 `kind` 区分**；或平台轻量提取候选后用户勾选确认）→ 生成 `plan_actions`。
- "半人工"落在「标注/确认」环节：平台零解析风险，用户始终掌控决策。

> 提示词措辞可随时调整，不阻塞开发。

## 6. 数据模型（新增 / 扩展）

一次"调控会话"包含**三个回合原文**，以 `gemini_final` 为执行依据。

### 6.1 `briefings`（提示词 / 简报）
| 字段 | 说明 |
|---|---|
| id, owner_id | — |
| role | `draft`(①→Gemini) / `review`(②→ChatGPT) / `final`(③→Gemini) |
| chief | 主事**角色平台**（`gemini` / `chatgpt`）——**不记型号版本**（见 Q3） |
| created_at | — |
| snapshot_json | 生成时的持仓/目标/素材快照（保证可回溯） |
| prompt_text | 完整提示词文本 |
| input_reply | 本轮所内嵌的上一轮原文（① 为空） |

### 6.2 `rebalance_plans`（调仓方案，一次会话一条）
| 字段 | 说明 |
|---|---|
| id, owner_id | — |
| created_at | — |
| gemini_draft | ① Gemini 初稿原文 |
| gpt_review | ② ChatGPT 审查原文 |
| gemini_final | ③ Gemini 终稿原文（**执行依据**） |
| status | draft / executing / done |

### 6.3 `plan_actions`（动作行，用户从终稿标注生成）
| 字段 | 说明 |
|---|---|
| id, plan_id | — |
| **kind** | **`rebalance`（调仓）/ `rule`（规则变更）** —— 两条主线共用一张表 |
| action | 调仓：减 / 加 / 换 / 持有；规则：修改 / 新增 / 废止 |
| target | 调仓：标的（projects.id 或代码）；规则：规则项 |
| target_weight / new_value | 目标权重 / 规则新值 |
| reason, trigger | 理由 / 触发条件（从终稿摘） |
| source_quote | 对应终稿原文片段（溯源） |
| status | 调仓：计划 / 部分 / 已完成 / 已取消；规则：已采纳 / 未采纳 |
| executed_at | — |

> 规则变更行**不进 Feedback 成交闭环**，但采纳后需**写回目标配置层并留痕**（见 §4.2.1）。

> 实际成交回填**复用现有 `Feedback`**，主事方案 = 组合级"建议"来源，进入「建议 → 反馈 → 再预测」闭环。

## 7. 圆桌重新定位（D4 已决）

### 7.1 定位：**多模型分析层（分析师团）**，保留不降级
- 席位输出的是**分析结论**（对持仓+新闻的判断与理由），不再是 BUY/SELL/HOLD 投票汇总。
- 汇总后的席位结论 = 主事提示词的**核心素材**输入。
- 取消"表决定调"语义；命中率统计保留数据、改语义为「**素材质量 / 分析师参考度**」（衡量席位分析对终稿的参考价值）。

### 7.2 席位获取方式：**方案 3 混合（维持现状，不动）**
- 有 API 的模型自动调用；无 API（仅网页端）的模型由用户手工粘贴回填。
- 结论：**本块 v2 不改造**。

## 8. 现状资产盘点（v1 已具备，v2 直接复用 / **不重建**）

> 本轮讨论关键结论：**"结构化卡片"在 v1 已落地，v2 无需重建卡片实体**，只需补"目标配置层 + 主事三轮模板"。

| 资产 | 落点 / 位置 | v2 怎么用 |
|---|---|---|
| **资讯结构化卡片** | `news_items.ai_*`：`ai_score`(1-5) / `ai_reason`(要点) / `ai_tags`(标签) / `ai_codes`(关联标的) / `ai_dup_of`(同题去重) | 直接作为**素材体** |
| 卡片加工 | `newsai.score_items()`（LLM 批量加工，源站刷新不覆盖 ai_*） | 复用，不动 |
| 卡片 UI 出口 | 资讯工作台（`static/js/08-news.js`：AI 徽标 / 推荐理由 / 标签 / 与持仓相关标记） | 复用，不动 |
| 选条与防重喂 | `newsai.select_news_for_prompt()` + `NewsInjectLog`（持仓代码∩ai_codes ∪ 行业画像命中、同题去重、"上次注入<今天"才排除、市场级保底 3 条） | 复用，不动 |
| 提示词渲染 | `newsai.news_prompt_block()`（编号 + ★ + 重要度 + 要点 + 关联标的，要求席位引用编号） | 复用，**只换指令尾** |
| 持仓快照 | `app._snapshot_prompt_text`（指数/账户/持仓涨跌） | 复用，作为上下文头一部分 |
| 行业分类 | `projects.category`（v1 新增） | 行业聚合占比 |
| **缺口：目标配置** | **v1 无** | **v2 新建**（见 §4.2） |

**结论**：v2 增量收敛为 —— **① 新建目标配置层；② 新建主事三轮提示词模板（复用现有装配）**。

## 11. v2 全量开发 · 实施顺序（建议）

| 顺序 | 范围 | 风险 |
|---|---|---|

| 5 | 跟踪闭环打通 Feedback（plan_action → 成交回填 → 复盘） | 中 |

## 12. 界面与工作流具体方案

> 状态：**已定 v0.1**（逐模块讨论完成，用户拍板"按建议设计"）。

### 12.1 页面骨架
- **入口**：顶部导航新增「主事工作台」，登录可见、游客隐藏。
- **形态**：**单页分步**，不跳页。
- **顶部状态条**：`① 规则审视 → ② 初稿 → ③ 审查 → ④ 终稿 → ⑤ 执行跟踪 → 完成`

### 12.2 分区与交互

| 步骤 | 内容 | 关键交互 |
|---|---|---|
| **① 规则审视**（每期必做） | 当前目标权重 / 纪律规则 / 风险偏好 + **近期政策·市场变化**（复用资讯卡片，★ 标相关） | 主事在三轮中给规则变更建议（§4.1），此处供对照裁定；采纳后写回配置并**留痕** |
| **② 初稿** | 生成提示词（上下文头 + 素材体 + 指令尾） | 一键复制 → 粘贴 Gemini 初稿 → 保存 |
| **③ 审查** | 自动内嵌 ② 初稿生成提示词 | 复制 → 粘贴 ChatGPT 审查 → 保存 |
| **④ 终稿** | 自动内嵌 ③ 审查生成提示词 | 复制 → 粘贴 Gemini 终稿 → 保存（**执行依据**） |
| **⑤ 执行跟踪** | 左：终稿原文（只读，可高亮定位）<br>右：标注清单，**分两组**（① 调仓 ② 规则变更） | 见 12.3 |
| **底部** | 历史会话（见 12.5） | 可回溯任意一次的三回合原文 |

### 12.3 ⑤ 动作行标注（两条主线）

- **动作行产生方式（已决）**：**平台轻量提取候选**（按编号/段落拆分终稿）→ 用户**勾选 / 删改 / 确认**。
  优于纯手填：终稿为自然语言，纯手工录入成本高；平台拆候选 + 用户确认，兼顾效率与终裁权。
- **调仓组**：逐条标 `计划 / 部分 / 已完成 / 取消` → 执行后**回填实际成交**（进 `Feedback`）。
- **规则组**：逐条标 `采纳 / 未采纳` → 采纳则**写回目标配置层并留痕**。
- **规则变更生效时机（已决）**：**立即生效**——规则变更本就是对当期政策/市场的反应，拖到下期会失去时效。

### 12.4 状态机
`审视中 → 初稿 → 审查 → 终稿 → 执行中 → 完成`
- 支持**回退**：某轮需要重跑（如初稿不满意）则回到该轮重新生成。

### 12.5 历史会话呈现
- **位置**：页面底部「历史会话」折叠区。
- **列表**：日期倒序，每条显示 `日期 / 状态 / 调仓条目数 / 规则变更数`。
- **详情**：点开可回溯**三回合原文**（初稿 / 审查 / 终稿）+ 当时标注的动作行 + 执行结果。
- **与规则留痕联动**：可查某次规则变更发生在哪期、什么背景、依据哪次主事建议。

### 12.6 遗留
- **无**。全部决策点（D1–D5、Q1–Q3）均已决，设计成熟，可进入开发。

## 13. 最小影响落地设计（v1 现存结构上的接入方案）

> 目标：在 **v1.0.0 稳定态**上满足 v2 全部设计，同时对既有代码的改动降到"加法"级别。

### 13.1 原则：加法不减法

### 13.2 后端落点

| `app.py` | ① import 追加 ② 追加约 8 个新端点 | 现有端点零改动 |

**新增表**（全部新表，`create_all` 自动建）：

| 表 | 用途 | 说明 |
|---|---|---|
| `chief_goals` | 目标配置层：`kind`(`weight`/`rule`/`preference`) + `key` + `value` + `updated_at` + `source_quote` + `note` | 承载 §4.2 目标权重 / 纪律规则 / 风险偏好；`note` 记留痕（哪期 / 什么背景 / 依据哪次建议）。<br>**`weight` 的 `key` 为 `"p:<project_id>"`（按标的**，已落地 A1）；行业占比由标的汇总，不单独存 |

### 13.4 界面形态：卡片序列（替代分步状态条）

§12.1 原设计为"单页分步 + 顶部五步状态条"。**改为纵向卡片序列**，复用圆桌已有的 `.rt-seat` 可折叠卡：

```
┌ 本期会话（状态：审视中 / 初稿 / 审查 / 终稿 / 执行中 / 完成）──────────┐
│ ▾ ① 目标与规则审视    [保存]                                        │
│    目标权重表（当前 vs 目标 / 偏离 / 超配·低配）· 纪律规则 · 风险偏好  │
│    近期政策与市场变化（资讯卡片，★ 标相关）                          │
├────────────────────────────────────────────────────────────────────┤
│ ▾ ② 初稿（→ Gemini）              [生成提示词] [复制] [保存答复]      │
│    [提示词文本框 / 答复粘贴区]                                       │
├────────────────────────────────────────────────────────────────────┤
│ ▾ ③ 审查（→ ChatGPT）  [自动内嵌②原文] [生成] [复制] [保存答复]       │
├────────────────────────────────────────────────────────────────────┤
│ ▾ ④ 终稿（→ Gemini）   [自动内嵌③原文] [生成] [复制] [保存答复]       │
├────────────────────────────────────────────────────────────────────┤
│ ▾ ⑤ 执行跟踪                                                       │
│    左：终稿原文（mdRender 渲染，只读）  右：动作行清单（分两组）      │
│       · 调仓组：计划 / 部分 / 已完成 / 取消 → 回填成交               │
│       · 规则组：采纳 / 未采纳 → 采纳即写回目标配置 + 留痕            │
├────────────────────────────────────────────────────────────────────┤
│ ▸ 历史会话（折叠，日期倒序：日期 / 状态 / 调仓数 / 规则变更数）       │
└────────────────────────────────────────────────────────────────────┘
```

**为什么改（取舍）**：
- 少造一个新组件（状态条 + 分步切换逻辑），直接复用圆桌的 `.rt-seat` 折叠卡与 `.rt-seat-actions` 按钮组 → 视觉语言天然一致；
- 五步**顺序即卡片顺序**，状态推进体现为卡片依次解锁，不需要额外的步骤状态管理；
- 支持回退（§12.4）：重跑某轮 = 清空该轮答复重新生成，卡片永远可见，不存在"当前在第几步"的隐藏态；
- 代价：首屏卡片较多（用折叠缓解，默认只展开当前待办轮）——**接受**。

**交互要点**：
- 折叠状态复用 `localStorage` 折叠集合（与 `RT_FOLD_KEY` 同款模式，独立 key）；
- ②③④ 的"生成提示词"由后端产出，前端只展示 + 一键复制 + 粘贴原文保存；
- 原文用 `mdRender()` 渲染（主事答复常为 markdown），可溯源；
- **动作行提取在前端做**：按编号 / 段落 / 行首关键词（`减仓|加仓|买入|卖出|规则|建议`）拆候选 → 用户勾选 / 删改 / 确认。**不调 LLM**，零解析成本与风险。

### 13.5 目标配置的落点

- 存 `chief_goals`（新表），**不进 projects、不进 admin 设置页**；
- UI 在 ① 卡内就地编辑保存，无需跳转；
- 规则采纳 → 写回 `chief_goals` 并在 `note` 记留痕（哪期 / 什么背景 / 依据哪次终稿）→ **立即生效**（§12.3）。

### 13.6 分期上线（每期独立可用，顺序即 §11）

| 期 | 交付 | 依赖 |
|---|---|---|
| 1 | ① 目标与规则审视卡（`chief_goals` + 页 + 路由接入） | 无（本期限可单独使用，不被依赖） |
| 2 | ②③④ 三轮提示词生成 + 原文留存 | 期 1（上下文头需目标配置） |
| 3 | ⑤ 执行跟踪（动作行标注 + 状态 + 规则采纳留痕） | 期 2 |
| 4 | 圆桌语义调整（措辞 / 命中率→素材质量）+ 历史会话区 | 无（可提前） |
| 5 | 成交回填打通 `Feedback` | 期 3 |

> 期 1 与期 4 无依赖，可先行；期 2 之前若圆桌未跑，素材体只带资讯卡片即可工作，不阻塞。
