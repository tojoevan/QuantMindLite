# QuantMindLite v2 设计方案：主事工作台（半人工决策闭环）

> 状态：v2 设计草案 v0.2（讨论成熟中，尚未实现）
> 前置版本：`v1.0.0`（已 tag 固化，含标的清单分类/筛选/排序/自动分类）
> 设计原则：平台**不做决策、不自动下单**；决策权归属单一主事；人工桥接（复制简报 → 问主事 → 贴回答复）。

---

## 0. 版本背景与定位

### v1 回顾（慢量化操作台）
- 核心理念：**建议 → 反馈 → 再预测** 的人机协作闭环，逐标的（micro）信号级。
- 能力：逐标的 BUY/SELL/HOLD 预测（`predictor.py`）、圆桌多 AI 席位分析、资讯工作台、论坛、组合可视化（持仓/盈亏/分类标签）。
- 短板：只回答"**这一只该买还是卖**"，缺"**我的整体组合健康吗、该往哪调**"的组合级合成。

### v2 目标
把平台从"逐标的信号"升级为"**组合级合理化建议与调控**"，引入：
1. **单一主事裁决**：把所有数据/分析/持仓/调整情况汇总交给顶级 AI 主事，由其给出调仓方案，用户执行。
2. **双主事串行审查**：Gemini 主动管理决策 + ChatGPT 反向思考审查，确保每笔调整都经双方分析。
3. **工作流化**：平台负责"归集 → 出简报 → 回收跟踪"，中间由用户手工桥接，即"半人工 / 半量化"。

---

## 1. 核心架构转向

| 维度 | v1（否定） | v2（采用） |
|---|---|---|
| 决策来源 | 多 AI 席位各投 BUY/SELL/HOLD → 机械汇总 | 单一主事裁决（Gemini 决策 + ChatGPT 审查） |
| 平台角色 | 既是分析方又是"汇总裁判" | 信息中枢 + 执行跟踪器 |
| 闭环层级 | 逐标的信号级 | 组合级（持仓聚合 → 主事方案 → 执行跟踪） |
| 下单 | 全人工 | 全人工（不变） |

**双主事串行模型（已决）**
- **Gemini = 主动管理决策**：基于完整简报产出主调仓方案。
- **ChatGPT = 反向思考审查**：对 Gemini 方案逐条挑刺 / 加风险警示 / 建议修正。
- **用户 = 最终裁定**：拿到"主方案 + 审查意见"后定稿可执行清单。
- 目标：**每一笔调整都经过两方分析审查、可追溯**。

---

## 2. 半人工工作流（阶段 0–5 + 审查）

| 阶段 | 执行方 | 平台职责 |
|---|---|---|
| 0 数据归集 | 自动 | 持仓/盈亏/分类/资讯/历史反馈（v1 已具备） |
| 1 分析素材 | 自动 | 圆桌席位产出**逐标的分析**（降级为"素材"，非决策） |
| 2a 决策简报 | 平台 → 用户 | 一键拼装自包含简报 → 复制给 Gemini |
| 3a 问主事 | **用户**（手工） | 粘贴进 Gemini，拿回主方案 |
| 2b 审查简报 | 平台 → 用户 | 生成审查简报（**内嵌 Gemini 主方案**）→ 复制给 ChatGPT |
| 3b 问审查 | **用户**（手工） | 粘贴进 ChatGPT，拿回审查意见 |
| 4 双份回填 | 用户 → 平台 | 粘贴 Gemini 主方案 + ChatGPT 审查意见 → 解析 |
| 4.5 裁定 | **用户** | 逐条确认/修改最终处置 |
| 5 实施跟踪 | 用户 + 平台 | 用户下单；平台标记计划/已执行/部分，回写实际成交 |

> 阶段 2（出）与阶段 4（进）是平台需新建的两个接口，3/5 为用户人工桥——这是"半量化"的实体形态。

---

## 3. 信息架构：新增「主事工作台」页

- **入口**：顶部导航新增「主事工作台」，登录可见、游客隐藏。
- **三段式布局**：
  - **左 · 简报生成**：选主事角色（决策=Gemini / 审查=ChatGPT）→ 一键生成 → 复制。一次点击出「决策简报」「审查简报」两块文本。
  - **中 · 调仓方案**：粘贴主方案 + 审查意见 → 解析清单 → 逐条裁定 → 跟踪。
  - **右/下 · 历史**：历次简报与方案，可回溯、可复用。
- **主事角色**：默认 Gemini=决策、ChatGPT=审查（可在设置中调整，但关系固定为"决策+审查"串行）。

---

## 4. 阶段 2 简报生成（出站）

### 4.1 决策简报（→ Gemini）
1. **持仓全景**：按行业聚合占比 + Top3 集中度 + 单一标的占比（复用 v1 分类标签）。
2. **逐标的近况**：盈亏、近期席位分析、近期资讯要点。
3. **历史调仓与反馈**：上次方案及实际表现（来自 Feedback）。
4. **明确指令**：「请以主事身份，基于以上给出调仓方案（减/加/换 + 目标权重 + 理由 + 触发条件）。」

### 4.2 审查简报（→ ChatGPT）
- 在决策简报基础上，**内嵌 Gemini 回传的主方案全文**。
- 指令：「请作为反向思考审查者，对主方案逐条给出**通过 / 驳回 / 风险警示**，并指出遗漏或过度冒险之处。不要另起一套方案，只做审查。」

### 4.3 工程要点
- 主事角色决定指令措辞风格。
- 持仓多时按**市值 TopN + 行业聚合摘要**截断，避免超出上下文。

---

## 5. 阶段 4 主事答复回填（入站，关键）

采用**约束格式回填**，不依赖二次 LLM 解析：

- 简报末尾要求主事用**固定表格**回复（列：动作 / 标的 / 目标权重 / 理由 / 触发条件）。
- 平台按表格解析 → 生成 `plan_actions` 草稿 → **用户逐条确认/修改** → 入库。
- 保留 `raw_reply` 原文备查。
- "半人工"落在「确认」环节：解析可靠、用户仍掌控决策。

### 裁定 UI
逐条展示三栏：**Gemini 主张 / ChatGPT 立场 / 你的处置**（通过/否决/改权重），可编辑最终目标权重。

## 6. 数据模型（新增 / 扩展）

### 6.1 `briefings`（简报）
| 字段 | 说明 |
|---|---|
| id, owner_id | — |
| role | `decision`(→Gemini) / `review`(→ChatGPT) |
| chief | 主事标识（如 `gemini-argon` / `chatgpt`） |
| created_at | — |
| snapshot_json | 生成时的持仓/分析快照（保证可回溯） |
| prompt_text | 完整简报文本 |

### 6.2 `rebalance_plans`（调仓方案）
| 字段 | 说明 |
|---|---|
| id, briefing_id | 关联简报 |
| role | `gemini`(主方案) / `chatgpt`(审查意见)，两计划互链 |
| chief | — |
| created_at | — |
| raw_reply | 主事原始答复（原文备查） |
| status | draft / reconciled |

### 6.3 `plan_actions`（调仓动作行）
| 字段 | 说明 |
|---|---|
| id, plan_id | — |
| action | 减 / 加 / 换 / 持有 |
| target | 标的（关联 projects.id 或代码） |
| target_weight | 目标权重 |
| reason, trigger | 理由 / 触发条件 |
| gemini_action | Gemini 原始主张（溯源） |
| chatgpt_verdict | ChatGPT 审查结论（通过/驳回/风险警示） |
| final_disposition | 用户最终处置 |
| status | 计划 / 部分 / 已完成 / 已取消 |
| executed_at | — |

> 实际成交回填**复用现有 `Feedback`**，主事方案 = 组合级"建议"来源，进入「建议 → 反馈 → 再预测」闭环。

---

## 7. 圆桌重新定位

- 席位分析 → 简报「**素材层**」（标注仅供参考），不再当决策。
- 命中率统计 → 改名「**素材质量**」，保留不删（作为素材可信度参考）。
- 取消"BUY/SELL/HOLD 汇总即决策"的语义。

---

## 8. 跟踪闭环

`plan_action` 标记完成 → 触发实际成交回填（Feedback）→ 进入「建议 → 反馈 → 再预测」；方案存档供复盘（`rtreview` 可纳入主事方案命中评估）。

---

## 9. 待决决策 / 开放问题（v2 设计期继续讨论）

| 编号 | 决策点 | 当前建议 |
|---|---|---|
| D1 | v2 实施先做哪些 | 阶段 2 简报先上（零风险、立即可用），阶段 4 跑顺后再做 |
| D2 | 主事答复格式 | 约束表格 + 人工确认（不靠二次 LLM） |
| D4 | 圆桌表决语义 | 降级为素材，统计改名「素材质量」 |
| D5 | 简报超长截断 | 市值 TopN + 行业聚合摘要 |
| Q1 | 审查粒度 | 三态（通过/驳回/风险警示）是否够？或要"修正后权重" |
| Q2 | 驳回终裁 | ChatGPT 驳回某项时，**最终拍板权始终归用户**，平台只呈现 |
| Q3 | 主事型号 | Gemini 具体型号（"argon"?）、ChatGPT 型号需在选项中准确标注 |

> 以上不阻塞 v2 启动；v2.0 仅落地阶段 2 出站简报即可开始人工闭环。
