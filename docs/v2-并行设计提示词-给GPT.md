# 给 GPT 的并行设计提示词（v2 主事工作台 · 界面与工作流）

> 用途：把本文档里的「完整版提示词」整段复制给 ChatGPT（或任意顶级思考模型），让它**独立设计一份界面与工作流方案**，用于与我方方案（v0.1）交叉对比。
> 前提：**不动代码**，只做设计。输出可以是设计文档，也可以是单文件 HTML 原型。

---

## A. 精简版（约 120 字，适合先开一轮发散）

```
我在做一个「慢量化操作台」的 v2 功能：主事工作台。定位是——平台不做决策、不自动下单，
只做「信息归集 → 生成提示词 → 回收主事答复 → 跟踪执行」；决策权交给顶级 AI 主事，
中间全部由我手工桥接（复制提示词去问模型，把答复贴回来）。
工作流是三段式串行：Gemini 出初稿 → ChatGPT 反向审查 → Gemini 出终稿 → 我执行。
请帮我独立设计这套界面的信息架构与分步工作流，并指出我已有方案（单页五步：规则审视/初稿/审查/终稿/执行跟踪）的问题与更好的替代。
```

## B. 完整版（推荐，直接用这个）

把下面代码块内的内容**整段复制**：

````
# 任务
请为我的 Web 应用「QuantMindLite（慢量化操作台）」的 v2 新功能「主事工作台」，
独立设计一份**界面与工作流方案**。你可以认同或推翻我已有的 v0.1 方案，但必须给出理由。
刚性问题（架构/决策流程）不要改，界面与工作流层面请放开设计。

# 一、产品定位（刚性）
- 平台**不做决策、不自动下单**，只做：信息归集 → 生成提示词 → 回收主事答复 → 跟踪执行。
- 决策权归属「主事」= 顶级 AI 模型；**人工桥接**：我复制提示词去各模型平台提问，再把答复原文粘贴回平台。
- 这是刻意保留的「半人工 / 半量化」形态：不追求自动化，追求**可追溯、经两方审查、我终裁**。
- 现有持仓规模：16 个标的（A 股 + 场内外基金），已有行业分类标签。

# 二、决策流程（刚性，不可改）
三段式串行闭环，每期跑一轮：
1. **Gemini 出初稿**：基于平台给的提示词（持仓全景 + 资讯素材 + 圆桌席位分析汇总），回答「是否需要调仓」+「调整指南」。
2. **ChatGPT 反向审查**：把 Gemini 初稿内嵌进提示词，要求它反向思考、挑刺、给风险警示与修正建议（**它不产出最终方案**，只是"砂纸"）。
3. **Gemini 出终稿**：把 ChatGPT 审查意见内嵌，要求综合出最终方案，并说明采纳/未采纳哪些审查意见及原因。
4. 我拿终稿执行；平台只留存原文，不自动执行。我可部分否决。

**两条并行主线**：每一轮提示词都同时要求主事输出
① 调仓建议（是否调仓 + 调整指南：减/加/换 + 目标权重 + 理由 + 触发条件）
② 规则变更建议（近期市场/政策变化是否要求调整我的纪律规则，如单一标的 ≤15%、单一行业 ≤40%）
两条主线地位相同，**都由我终裁**：调仓→去执行；规则→我决定采不采纳，采纳则立即生效并留痕（何时/什么背景/依据哪次建议）。

# 三、提示词的信息结构（可优化措辞，但三层结构固定）
每次生成的提示词 = 上下文头 + 素材体 + 指令尾：
- **上下文头**：持仓全景（持仓/盈亏/行业分类/行业占比/集中度）、最近调仓与执行结果、投资目标（目标权重 + 纪律规则 + 风险偏好）
- **素材体**：近期资讯要点（已由平台 LLM 加工成结构化卡片：重要度 1-5 / 一句话要点 / 关联标的 / 标签）、圆桌各 AI 席位的分析结论汇总
- **指令尾**：角色设定 + 输出要求（三轮各不同）
- 截断策略：资讯约 10 条；持仓 ≤20 全带明细，>20 取市值 Top15 + 其余按行业聚合摘要；席位结论**按标的聚合**成"共识 + 分歧"，不逐席位贴全文。

# 四、已有的 v0.1 界面方案（请你评审 / 改进 / 替代）
- 顶部导航新增「主事工作台」，登录可见、游客隐藏；**单页分步**，不跳页。
- 顶部状态条：① 规则审视 → ② 初稿 → ③ 审查 → ④ 终稿 → ⑤ 执行跟踪 → 完成
- ① 规则审视：展示当前目标权重 / 纪律规则 / 风险偏好 + 近期政策与市场变化（资讯卡片），供我对照主事建议做裁定
- ②③④：各生成对应提示词（自动内嵌上一轮原文）→ 一键复制 → 我粘贴主事答复 → 保存原文
- ⑤ 执行跟踪：左＝终稿原文（只读），右＝标注清单，**分「调仓」「规则变更」两组**；
  动作行由平台**轻量提取候选**（按编号/段落拆终稿）→ 我勾选/删改/确认；
  调仓组标 计划/部分/已完成/取消 并回填实际成交；规则组标 采纳/未采纳，采纳即写回配置并留痕
- 状态机：审视中 → 初稿 → 审查 → 终稿 → 执行中 → 完成，支持回退到任一轮重跑
- 底部「历史会话」折叠区：日期倒序（日期/状态/调仓数/规则变更数），点开可回溯三回合原文 + 动作行 + 执行结果，并与规则留痕联动

# 五、视觉约束（必须遵守）
- 暗色主题，沿用平台现有设计令牌：
  `--bg:#0d1117` `--panel:#161b22` `--panel-2:#1c2330` `--border:#21262d` `--border-strong:#30363d`
  `--text:#e6edf3` `--text-2:#c9d1d9` `--muted:#8b949e` `--accent:#388bfd`
  `--green:#3fb950` `--red:#f85149` `--yellow:#d29922` `--radius:12px`
  间距刻度 4/8/12/16/22/30px；字号 12/13/14/15/18/22px
- 风格：极简紧凑，信息密度高，不铺大留白、不做营销式观感；涨红跌绿（A 股习惯）。
- 技术形态：零构建原生三件套（HTML + CSS + 原生 JS），不引入框架。

# 六、请你输出
1. **工作流设计**：步骤编排（可与我的五步不同）、每步的输入/输出/异常与回退处理；说明你增删了哪一步及理由。
2. **界面布局**：分区方式（单页分步 / 左右分栏 / 其他）、导航与状态呈现、每个分区的内容与关键交互。
3. **三轮提示词的模板草稿**：至少写出三轮的「指令尾」全文，以及上下文头与素材体的组织方式（可直接给 Markdown 模板）。
4. **标注与跟踪环节的交互细节**：终稿原文 ↔ 动作行的联动、轻量提取怎么呈现、规则采纳如何留痕与回看。
5. **对 v0.1 的批评**：明确指出你认为不合理/可简化的地方，给出替代方案与权衡。
6. **数据模型补充意见**：我已规划 `briefings`（三轮提示词，含 role/snapshot_json/prompt_text/input_reply）、
   `rebalance_plans`（gemini_draft / gpt_review / gemini_final / status）、
   `plan_actions`（kind=rebalance|rule、target、target_weight|new_value、reason、trigger、source_quote、status、executed_at）。请指出缺漏。
7. **可选**：如果方便，另外产出一个**单文件 HTML 可交互原型**（内联 CSS/JS、演示数据即可，可点击切换步骤、可复制提示词），让我直观对比。

约束：不要建议自动下单或全自动调用主事 API——人工桥接是刻意设计。
请给出有主见的方案，而不是罗列选项让我选；若有取舍，直接说明你选了什么、放弃了什么。
````

## C. 使用建议

- 想**发散**：先用 A 版，拿到思路后再用 B 版收敛成可对比的正式方案。
- 想**直接对比**：只用 B 版，并要求它同时输出第 7 项（HTML 原型），可与仓库里的
  `docs/v2-主事工作台-原型.html`（我方 v0.1 原型）并排看。
- 拿到 GPT 方案后，对比要点建议聚焦三处：**步骤编排**、**标注环节的人机分工**、**历史回溯的粒度**。
